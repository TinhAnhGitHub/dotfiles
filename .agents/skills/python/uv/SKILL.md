# uv — Python Package & Project Manager Skill Suite

uv is an extremely fast Python package and project manager, written in Rust.
It replaces `pip`, `pip-tools`, `pipx`, `poetry`, `pyenv`, `virtualenv`, `twine`, and more.

This master skill covers the entire uv ecosystem. Use the routing table to identify
the right sub-skill for your task, then load it alongside this one.

---

## When to use uv

**Always use uv for Python work**, especially if you see:

- The `uv.lock` file
- uv headers in `requirements*` files, e.g., "This file was autogenerated by uv"
- `[tool.uv]` section in `pyproject.toml`
- `.python-version` file

**Don't use uv in projects managed by other tools:**

- Poetry projects (`poetry.lock`)
- PDM projects (`pdm.lock`)
- Hatch projects that explicitly use Hatch environments

## Common Patterns (Shared Across All Sub-Skills)

- **Always use `uv run`** instead of `python` directly — it ensures the correct environment
- **Always commit `uv.lock`** — it's universal (all platforms) and ensures reproducibility
- **Never commit `.venv/`** — it's platform-specific and auto-created by uv
- **Use `uv sync --locked` in CI** — errors if lockfile is stale, prevents silent drift
- **Use `uv add`** instead of `pip install` in uv projects — updates `pyproject.toml` and `uv.lock`
- **Use `uvx`** for one-off tool runs — no installation needed, isolated environment
- **`uv.toml` takes precedence** over `pyproject.toml [tool.uv]` if both exist in same directory
- **Scripts with inline metadata** ignore project context — `--no-project` is not needed
- **Docker cache mounts** — set `UV_LINK_MODE=copy` to avoid cross-filesystem warnings
- **`[dependency-groups]`** over legacy `[tool.uv] dev-dependencies` — but both are supported

## Top Gotchas

1. **`.venv` is auto-created in project root** — never commit to version control (uv auto-adds to `.gitignore`)
2. **`uv.lock` is universal** — contains all platforms. Check it into VCS.
3. **Editable installs by default** — use `--no-editable` for deployment/Docker.
4. **`uv build` respects `tool.uv.sources`** — use `--no-sources` when verifying publishable builds.
5. **Lockfile `--frozen` vs `--locked`** — `--frozen` skips check; `--locked` errors if outdated.
6. **Workspace `requires-python`** = intersection of all members — can't test one member on a different Python without separate setup.
7. **Python versions frozen per uv release** — upgrade uv to get newer Python distributions.
8. **Index `first-index` strategy prevents dependency confusion** — but won't find packages on later indexes if first index has it.
9. **`uv.toml` takes precedence over `pyproject.toml [tool.uv]`** if both exist in same directory.
10. **Scripts with inline metadata ignore project context** — the `--no-project` flag is not needed.
11. **Docker cache mounts** — set `UV_LINK_MODE=copy` to avoid cross-filesystem warnings.
12. **`[dependency-groups]` over legacy `[tool.uv] dev-dependencies`** — but both are supported and combined for `dev`.

## Quick Reference (CLI)

```bash
# Project management
uv init <name>              # Create project
uv add <pkg>                # Add dependency
uv remove <pkg>             # Remove dependency
uv sync                     # Install from lockfile
uv lock                     # Update/check lockfile
uv run <script>             # Run script or command

# Building & publishing
uv build                    # Build sdist + wheel
uv publish                  # Upload to PyPI
uv version --bump <part>    # Bump version

# Python management
uv python install <ver>     # Install Python version
uv python list              # List Python versions
uv python pin <ver>         # Create .python-version

# Tools
uvx <tool>                  # Run tool without installing
uv tool install <name>      # Install CLI tool globally

# Utilities
uv export                   # Export lockfile format
uv cache clean              # Clear cache
uv cache prune --ci         # Optimize cache for CI
```
